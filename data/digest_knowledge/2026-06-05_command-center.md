## Recommendations

- [LARGE] Harden Agent Memory & Knowledge Graph Reliability
  Given the 'hallucination at scale' warning, implement a multi-layered validation strategy for 'command-center's knowledge graph and cross-session memory. Instead of relying solely on embedding proximity for memory recall, integrate explicit semantic validation or rule-based checks. Design agent 'projects' with strict instruction sets for grounding facts and sources.
  Inspired by: Post 29, Post 75, Post 61
  Impact: Significantly reduce agent hallucinations and improve the trustworthiness and accuracy of briefings, digests, and task aggregation, making 'command-center' more reliable.
  Where it fits: Core agent framework, MEMORY.md auto-write, knowledge graph patterns for all spokes (crumbl-ops, healthpulse, wealth-mgmt), and the Sara digest agent.
  First step: For the 'Sara digest' agent, identify 5-10 critical facts Michael expects it to remember. Implement a separate agent or function that 'red-teams' the draft digest specifically for factual inaccuracies or ungrounded statements against these known facts, logging any discrepancies for review.
  Risks: Increased complexity in agent design, potential performance overhead from additional validation steps, initial development time to formalize knowledge structures and validation rules.

- [MEDIUM] Implement Proactive Multi-Turn Prompt Injection Defenses
  Proactively integrate multi-turn prompt injection defenses for all agents that process user-controlled inputs (email content, transcripts, iMessage). This should include strict input sanitization, explicit instruction to ignore adversarial prompts, and consider sandboxed execution for any code generated by agents based on these inputs.
  Inspired by: Post 66, Post 102, Post 83, Post 47, Post 59, Post 76
  Impact: Significantly mitigate security risks, prevent agents from being exploited to leak sensitive information, or executing unintended actions, ensuring the integrity and privacy of 'command-center'.
  Where it fits: Email triage agent, iMessage monitor, meeting transcript debriefs, and any future agents processing external text. Also applies to 'hooks and pre/post tool use automation' in Claude Code.
  First step: For the 'iMessage monitor' agent, develop a set of adversarial test cases (multi-turn prompts attempting to extract data or perform unauthorized actions). Create a simple automated test harness that feeds these inputs to the agent and asserts that it rejects the malicious intent and logs the attempted injection.
  Risks: Overhead in implementing and maintaining security measures, potential for false positives blocking legitimate inputs, continuous need to update defenses as new attack vectors emerge.

- [MEDIUM] Build Agent Token Usage & Decision Observability
  Develop a dedicated system to track token consumption per agent/model (Claude Code, Gemini) and log key agent decisions, tool calls, and execution traces. This observability will be crucial for managing costs, debugging agent behavior, and continuously improving decision quality and efficiency.
  Inspired by: Post 5, Post 19, Post 45, Post 42, Post 82, Post 9
  Impact: Gain precise control over AI costs, quickly identify inefficient prompts or agents, and establish a feedback loop for 'agent decision quality' and 'token efficiency', turning AI usage into measurable value.
  Where it fits: MCP server design, Python agents (email triage, daily briefing, meeting prep, Sara digest, iMessage monitor), integration with 'structlog' for structured logging.
  First step: Modify the 'email triage' agent to log LLM API calls (model used, input/output token counts, API call duration) to a simple file or SQLite table. Create a basic Python script that aggregates and visualizes this data (e.g., daily token spend per model, average processing time).
  Risks: Initial development effort for logging and dashboarding, ensuring the logging itself is token-efficient, managing the volume of observability data.

Empower agents with broader access to Michael's 'organizational memory' (GitHub Issues, Calendar) and a 'skills library' to anticipate needs, resolve conflicts, and pre-prepare information without explicit prompting.
