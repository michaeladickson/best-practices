## Recommendations

- [MEDIUM] Implement Claude Code Goal Engineering
  Integrate Claude Code's native 'Goal Engineering' capabilities (e.g., the `/goal` feature) into your development workflow. Define explicit, verifiable completion criteria for tasks, allowing Claude to autonomously iterate and self-verify its work. This will move human engineers to an 'on-the-loop' verification role.
  Inspired by: Post 80 (Goal Engineering), Post 111 (Mastering Fable 5), Post 133 (Anthropic's eval-driven development), Post 96 (Shipping code without human verification).
  Impact: Significantly increase Claude Code session efficiency, reduce developer oversight for iterative tasks, improve code quality by enforcing verifiable outcomes, and accelerate the development velocity for the small engineering team.
  Where it fits: CLAUDE.md guidelines, `knowledge/ system` for task definitions, `skills/` for integrating verification logic.
  First step: Experiment with Claude Code's `/goal` feature for a small, well-defined coding task (e.g., refactoring a specific utility function or writing a new unit test) and measure the reduction in human interaction and iteration count.
  Risks: Initial setup learning curve; potential for poorly defined goals to lead to irrelevant or incorrect output; over-reliance on agent self-verification without robust human oversight could introduce subtle bugs.

- [LARGE] Harden AI Agent Security and Permissions
  Review and implement strict, non-natural-language-based permission boundaries and hardened sandboxing for all operational AI agents (Gemini for invoice extraction/email classification, MCP server for QBO queries). Focus on decoupling agent credentials from their memory, utilizing just-in-time authorization for tool calls, and regularly auditing agent activities.
  Inspired by: Post 14 (Cybersecurity incidents), Post 49 (Anthropic incidents), Post 62 (AI agent permission boundaries), Post 74 (Anatomy of agent intrusion), Post 90 (Hardened agent runtimes), Post 112 (Agentic credentials).
  Impact: Significantly reduce the risk of accidental or malicious agent misuse, prevent unauthorized data access or exfiltration (especially for sensitive financial data), and ensure compliance with security best practices, crucial for protecting the business as it scales.
  Where it fits: GCP Cloud Run configuration, FastAPI middleware for tool access, Gemini configuration for external calls, PostgreSQL access control, and a dedicated security policy for agentic workflows.
  First step: Conduct a security audit of current Gemini and MCP agent configurations, specifically mapping out all external API access points and their associated permissions, then prioritize implementing least-privilege access and explicit authorization mechanisms for critical actions.
  Risks: Increased complexity in agent deployment and management; potential for over-restriction to hinder agent functionality; ongoing maintenance effort to keep up with evolving threats and agent capabilities.

  Inspired by: Post 135 (Balance Sheet Analyst with Claude), Post 48 (AI is eating Finance), Post 100 (Looker Agentic Workflows for RCA), Post 105 (Codex for Knowledge Work).
